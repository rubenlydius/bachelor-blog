Our low-poly lily generator was a good start, but for our style we wanted to try flowers that look a bit more realistic, and that can grow, bloom and breathe on the wall. So I learned to model a lily myself in Blender and figured out how to make it move in a way that also works in code.

## Learning from tutorials

I had never modelled a flower before, so I started with tutorials. One of them was even about a lily, and the other one was about a hibiscus (the video it was based on):

## Plane and simple petals

Every petal starts as a plain plane. I shaped and bent it into a petal, and then gave it a photo of a real lily petal as its texture. In the Shading tab, the image goes into the Base Color of the material, and I adjusted settings like the roughness until it looked soft instead of plastic. Then I went into UV editing to map the petal to the image. After the petals, I made the stem, the stamens and the leaves, and added more textures. In the end I had a few versions of the lily, from wide open to more trumpet-shaped and curled, and four kinds of leaves.

## Making it move

Next, I wanted the flowers to move. My first idea was to animate them in Blender with Geometry Nodes or the cloth simulator, which can make petals bend really naturally:

- <a href="https://www.youtube.com/watch?v=VVK7n9rMsHI" target="_blank" rel="noopener noreferrer">https://www.youtube.com/watch?v=VVK7n9rMsHI</a>
- <a href="https://www.youtube.com/watch?v=XS3JpWs9sIg" target="_blank" rel="noopener noreferrer">https://www.youtube.com/watch?v=XS3JpWs9sIg</a>

But then I found out that those animations don't come along when you export the model to code. A simulation or a node setup only exists inside Blender. So I looked into shape keys instead:

- <a href="https://www.youtube.com/watch?v=B11XBZmIIZc" target="_blank" rel="noopener noreferrer">https://www.youtube.com/watch?v=B11XBZmIIZc</a>
- <a href="https://www.youtube.com/watch?v=p5syxlEsc7U" target="_blank" rel="noopener noreferrer">https://www.youtube.com/watch?v=p5syxlEsc7U</a>

A shape key is a second version of the same model, where the same points are just moved somewhere else. For example, one key where the lily is a closed bud, and one where it's fully open. When I export the model, the shape keys come along as morph targets, and in code each one is a value from 0 to 1. That way I can mix them live: half open, a little breath, a bit of wind.

I made these shape keys:

- **Lilies:** bloom (from closed bud to open flower), breathe, and two sway keys for wind.
- **Leaves:** grow, breathe, two sway keys, curl (the tip rolls back) and roll (the edges roll up).

## Testing in code

To test the animations, I loaded the models into a small Three.js page with sliders for bloom, breathe and sway, and a button that breathes automatically: 4 seconds in, 6 seconds out. A flower only breathes as much as it's open, so a closed bud stays still. The sway is made from two slow waves that are out of sync, so it never looks like the same loop over and over.

<figure class="wide">

```js
for (const m of lilyMeshes) {
  const d = m.morphTargetDictionary; // shape key name → index
  m.morphTargetInfluences[d.bloom] = bloom;
  m.morphTargetInfluences[d.breathe] = breath * bloom; // only breathe when open
  // idle sway: two slow, out-of-phase waves, so the wind never looks looped
  m.morphTargetInfluences[d.sway_a] = swayA * swayAmount * bloom;
  m.morphTargetInfluences[d.sway_b] = swayB * swayAmount * bloom;
}
```

<figcaption class="mono">Every frame, the shape keys from Blender are mixed in code with values from 0 to 1.</figcaption>
</figure>

As I was coding, I also looked into different lily variants. I saw some lilies' petals roll way back, so I added a new shape key for curl. And now every leaf also gets its own timing and a random amount of curl and roll, so they don't all move together.

## Lilies don't grow from seeds

For our first scene, we planned to water seeds. Then I found out that lilies don't grow from seeds like that, but from bulbs. So I looked at real lily bulbs and made a few versions. Some looked too much like garlic cloves, others like an onion or even an artichoke. In the end I took one and adjusted it myself until it looked right. I added photo textures for the bulb skin, the roots and the shoot.

<ImageRow wide caption="From garlic-like to artichoke-like, to my final version, and the final bulb waking up.">
  <Figure src={bulbs} alt="Photos of real lily bulbs next to sketches, then several modelled bulbs in Blender, from garlic-like and artichoke-like to the final bulb with roots and a green shoot" />
  <Video src={bulbVideo} ratio={564 / 854} title="The final bulb on a black background waking up: roots grow out from underneath" />

The bulb got its own shape keys: sprout, breathe and three groups of roots that start growing one after another. At the tip of the shoot, I placed an invisible marker, so later I can grow the stem even more (subject to change). When the bulb wakes up, the roots grow first, then the shoot appears.

<figure class="wide">

```js
const t = (now - bulb.wakeStart) / 1000; // seconds since the bulb woke up
// roots
bulb.roots = ease(clamp01(t / 3));
// shoot
bulb.sprout = ease(clamp01((t - 1.5) / 3));
```

<figcaption class="mono">The timing of a waking bulb: first the roots, then the shoot.</figcaption>
</figure>

## What I learned

- Modelling with planes and photo textures is a quick way to get realistic-looking flowers that are still light enough for real time.
- Think about the export early, because not everything you make in Blender works in code, and shape keys turned out to be the bridge between the two.
- Check the real thing, a lesson I should have learned by now. You would think that looking up how lilies actually grow is the first thing we researched, but no: they grow from bulbs.
